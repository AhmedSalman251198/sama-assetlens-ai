# AssetLens AI R22 — نسخة محلية مرشحة للتحقق على بيئة المستخدم

## الجديد في R22

- منع طبقة المساعد العائم المغلقة من اعتراض النقرات خارج عناصرها المرئية، مع `inert` للحوار المغلق وحالات تركيز ولمس أوضح.
- عدّ إجمالي الأصول المصرح بها مباشرة من سجل المشروع بالعربية والإنجليزية، من دون تمريره على البحث النصي أو ادعاء أنه جواب AI.
- تثبيت اختيار المشروع وتبويبات Asset Intelligence ضد الاستجابات القديمة، وإتاحة التنقل بأسهم لوحة المفاتيح.
- Gemini من جهة الخادم فقط، وتحليل إصلاح/استبدال حذر يستخدم التكلفة المسجلة والحالة والأهمية وتأثير العلاقات، من دون أسعار سوق مختلقة.
- خريطة AI Confidence Map تفصل السجلات المقيمة فعليًا بالذكاء الاصطناعي عن الإدخال اليدوي أو غير المقيم.
- ربط مالي وفني منظم لاستيراد Excel/CSV، وحفظ القيم الخام عند غموض العملة أو الوحدة بدل اختراع تحويل.
- حذف جماعي ذري حتى 50 أصلًا بعد فحص صلاحية كل أصل وتأكيد واعٍ بعدد الأصول.
- يلزم تطبيق الترحيلين `017_assistant_access_and_incomplete_imports.sql` ثم `018_unverified_asset_relationships.sql` على Staging قبل النشر.

نجح محليًا ESLint وTypeScript وبناء Next.js و70/70 اختبار جودة، وفحص الاعتمادات أظهر صفر ثغرات معروفة. هذا لا يثبت نجاح Supabase الحقيقية أو جلسات الحساب أو اللمس والطباعة وQR في الأجهزة الفعلية؛ راجع `R22_TEST_REPORT_AR.md`.

## الجديد في R20

- «اسأل AssetLens» يستطيع استخدام `GEMINI_API_KEY` أو `OPENAI_API_KEY` من الخادم لتفسير سؤال المستخدم في نطاق أصول مشروعه ثم حساب الإحصاءات من كل السجلات المطابقة وتوليد إجابة مسندة إلى سجل المشروع. تظهر الأصول المشار إليها فقط عندما تكون الإحالات إلى سجلات مطابقة معروفة، وتوضح الشاشة إن كانت التفاصيل عينة من أول 60 أصلًا عالي المخاطر.
- إذا غاب المفتاح أو تعذر المزود، تعرض الشاشة **بحثًا في السجل** بعلامة صريحة، وليس تقريرًا مولدًا بالذكاء الاصطناعي. لا تُرسل كلمة المرور أو مفتاح Gemini إلى المتصفح؛ تصل بيانات المشروع إلى المزود فقط عند استخدام السؤال. تحقق بشريًا من الاستنتاجات قبل اعتماد قرارات مالية أو تشغيلية.
- معاينة ملف الاستيراد تسمح بتحديد صف العنوان لكل ورقة وإعادة المعاينة قبل الحفظ؛ تتحقق المعالجة من أن عدد `المستورد + المكرر + المرفوض` يساوي عدد صفوف المصدر، وترفض إعلان النجاح إن بقي صف دون مصير معروف. تُعطى العناوين المعروفة أولوية على صف بيانات عريض.
- تحسين قراءة الأزرار وحالة الاتصال وقائمة الحساب في الوضع الليلي، مع إصدار جديد من الـPWA للتخلص من الواجهة المخزنة القديمة.
- 51 اختبارًا محليًا تشمل 2,237 صف XLSX على ورقتين و2,013 صف API على قاعدة وهمية، إضافة إلى مساري Gemini وOpenAI مقلّدين، واختبار سباق تبديل جلسات الحساب؛ راجع `R20_TEST_REPORT.md` قبل النشر.

**لا يمكن ضمان قراءة كل ملف Excel كيفما صُمم**: يدعم `.xlsx` و`.csv` و`.tsv` حتى 100,000 صف مع تعديل ربط الأعمدة وصف العنوان من المعاينة؛ تحتاج ملفات `.xls` القديمة للتحويل أولًا. لم يُختبر ملف العميل الفعلي ولا الاتصال بمشروع Supabase أو Gemini الحقيقي أو QR مطبوع بكاميرا هاتف ضمن النسخة المحلية.

شغّل migrations بالترتيب حتى `supabase/migrations/016_harden_qr_and_hierarchy.sql` في Staging قبل النشر، ثم اختبر صلاحيات الأدوار وربط المشروع والتزامن والاحتفاظ بالصور.

- مساحة Asset Intelligence: رسم تبعيات الأصول، محاكاة ميزانية الاستبدال، سؤال قائم على بيانات السجل وDigital Twin مكاني خفيف، مع تحديد صلاحيات الصفحة.

## التشغيل المحلي

```bash
npm ci
cp .env.example .env.local
npm run dev
```

ثم افتح `http://localhost:3000`.

املأ `.env.local` بالقيم الصحيحة:

```env
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
SUPABASE_SECRET_KEY=YOUR_SERVER_ONLY_SECRET_KEY
# Legacy fallback: SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY

AI_PROVIDER=gemini
GEMINI_API_KEY=YOUR_GEMINI_KEY
GEMINI_MODEL=gemini-3.7-flash

# بديل اختياري
OPENAI_API_KEY=
OPENAI_VISION_MODEL=gpt-4o

NEXT_PUBLIC_SITE_URL=http://localhost:3000
CRON_SECRET=GENERATE_A_LONG_RANDOM_SECRET
```

يمكن للمستخدم إدخال مفتاح Gemini داخل شاشة Capture؛ يُحفظ في `sessionStorage` للتبويب الحالي فقط ولا يُكتب في قاعدة البيانات.

## خريطة الصفحات

| المسار | الوظيفة |
|---|---|
| `/` | مؤشرات وشارتات فقط: الجودة، Criticality الشعاعي، التأثير الموزون، المشاريع وتغطية المواقع |
| `/capture` | كاميرا/رفع، موقع الأصل، GPS، Barcode، Offline وطابور AI |
| `/assets` | يحوّل تلقائيًا إلى التقارير؛ سجل الأصول موحّد داخلها |
| `/organization` | خريطة المشاريع والمباني والطوابق والزونات |
| `/locations` | إدارة الأصول وحالتها وأهميتها وتصنيفها وبيانات دورة حياتها |
| `/transfers` | نقل أصل داخل مشروعه فقط مع تحقق من الموقع |
| `/reports` | فلاتر متقدمة، جودة، QR، Excel، تقرير AI PDF واستيراد Legacy |
| `/intelligence` | التبعيات وخطط الاستبدال والسؤال على البيانات وDigital Twin |
| `/admin` | المشاريع والمواقع والمستخدمون والقواعد وسجل التدقيق |

## ملاحظات الإنتاج

- استخدم `npm ci` في CI حتى يلتزم `package-lock.json` حرفيًا.
- اترك Supabase RLS مفعلة. يستخدم الخادم `SUPABASE_SECRET_KEY` (أو `SUPABASE_SERVICE_ROLE_KEY` القديم) فقط لإنشاء حسابات Auth وإعادة تعيين كلمات مرور المستخدمين؛ لا تسمّه مطلقًا `NEXT_PUBLIC_*` ولا تستخدمه في أي Client Component. تغيير المستخدم لكلمة مروره الشخصية يتم بجلسة دخوله ولا يحتاج المفتاح السري.
- طبّق migration `006` بعد `005` للحصول على Snapshot محسّن للداشبورد والإعدادات وبيانات المستخدم؛ توجد مسارات fallback تلقائية قبل تطبيقها لكنها أبطأ.
- طلب الرفع بعد التحسين لا يتجاوز 4 MB لتفادي حدود أجسام الطلبات الشائعة في Serverless.
- طابور التحليل يحد كل مستخدم بـ50 مهمة نشطة ويعالج مهمة واحدة ذريًا في كل مرة.
- راجع [VERCEL_DEPLOYMENT.md](./VERCEL_DEPLOYMENT.md) للنشر.
